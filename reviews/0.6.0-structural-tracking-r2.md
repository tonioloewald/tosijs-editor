## BLOCKERS

### B‑1 — Dropping a superseded proposal orphans the earlier change, so a chain of merges resolved per id loses text or duplicates it

**`src/tosijs-styled-editor.ts:1389, 1401, 1408`** · correctness + blast-radius, both verified independently · **this is the prior review's B‑1 returning through its own remediation**

`trackStructuralEdit` computes `superseded` purely structurally — any `blocksOut` entry whose sole element child is a `<tosi-ins[data-block-insert]>` — excludes it from `trackDeletion`, and `block.remove()`s it. Nothing re-stamps or re-parents the earlier gesture. The commit that removed absorption (`4522e37`) removed the re-stamp loop the drop depended on and kept the drop.

Reproduced five ways. `<p>Alpha.</p><p>Beta.</p><p>Gamma.</p>`, tracking on, Backspace at the start of `Beta.` (id1), then at the start of `Gamma.` (id2). `changes.filter(c => c.id === id1).map(c => c.kind)` is `['delete','delete']` — a change with a delete half and **no insert half**, a state no gesture produces.

- `acceptChanges(id1)` then `rejectChanges(id2)` → **`Gamma.`** — Alpha and Beta are gone from a document with zero pending changes, and nothing ever proposed deleting them without a replacement.
- `rejectChanges(id1)` then `acceptChanges()` → **`Alpha. | Beta. | Alpha.Beta.Gamma.`** — each appears twice in a fully resolved document.

**This is not the documented "visibly contradictory choice."** CHANGELOG licenses the duplication case on the rationale "Both are on screen when you choose." The superseded proposal was _deleted from the DOM_, so it is not on screen; after resolving one id the UI can only show "alex deleted Alpha., alex deleted Beta.", and accepting that is the faithful reading of what is displayed. Two corrections that widen it beyond the filed text: it needs **no second author** (one person pressing Backspace twice reaches it), and `changes` affirmatively _misreports_ a proposed merge as a bare two-paragraph deletion — the README's "every mark keeps its own id and stays independently resolvable" is false for the superseded mark.

Counterfactual checked: had the superseded block been struck instead of dropped, the same two calls yield `<p>Alpha.Beta.</p><p>Gamma.</p>` — correct. Supersession is the direct cause, not partial resolution in general.

Coverage: `src/tosijs-styled-editor.test.ts:1892` ("a chain of merges leaves no intermediate proposal behind") asserts exactly the orphan — 3 `data-block-delete`, 1 `data-block-insert` — and only exercises accept-all/reject-all, the two orders that happen to be clean.

**Fix:** before `block.remove()`, re-stamp every mark carrying the superseded proposal's `data-change` with the new gesture's id (chain stays one resolvable unit); or refuse to supersede a proposal whose `data-author`/`data-session` is not the current editor's and strike it as ordinary content. Either restores the invariant that **no change id can hold a delete half with no insert half**. Test: a two-merge chain resolved per id in both orders, same-author and foreign-author.

### B‑2 — With tracking OFF, Backspace/Delete across a list or table boundary silently destroys a character and performs no merge

**`src/tosijs-styled-editor.ts:2786, 2842, 2903, 2920`** · correctness, verified · **new regression in the default mode**

`deletionTarget(ip, this.parts.doc, 'back')` is doc-scoped and returns a leaf inside the previous block. The tracked branch — the only place `canMergeBlocks` can refuse _before anything moves_ — is skipped entirely when `trackChanges` is false, so the character deletion at :2834 runs unconditionally, and only then does the new `canMergeBlocks([deletionBlock, caretBlock])` clause veto the merge.

Measured, tracking off (the default, i.e. every existing user):

- `<ul><li>one</li><li>two</li></ul><p>Beta.</p>`, caret at start of `Beta.`, Backspace → `<li>tw</li>`. Three presses → `<li></li>` gone. No merge, `changes.length === 0`, **no `structural-edit-refused` event** (`refuseStructural` is unreachable on this path, so a host cannot even detect it).
- Grid table is worse: one Backspace removes the whole `<li>b</li>` via `removeNode(topSingleParentAncestor(node))`; three presses **delete the entire table**.
- `forwardDelete` has the identical shape (`<p>Alpha.</p><ul><li>one</li>…`, Delete at end of `Alpha.` → `<li>ne</li>`).

On master this keystroke merged (badly — loose text in the `<ul>`, which is what the guard exists to stop). The character loss is pre-existing; **the guard added by `9e5a3c1` converts the gesture into pure, unbounded loss with no structural change to explain it.**

The shipped test `'UNTRACKED, a list is not merged into a paragraph either'` (:1810) asserts only that a `<p>` survives, that "Beta." is present, and that no loose text follows `</li>` — it never asserts the list's own content, and passes green against this behaviour.

**Fix:** hoist mergeability into the gate for the whole gesture, not just the merge — in `backspace()`/`forwardDelete()`, when `crossesBlocks && !canMergeBlocks(pair)`, return without consuming anything, tracking on or off. Then strengthen the test to assert the neighbouring block's `textContent` is byte-identical, and confirm it fails first.

### B‑3 — `blockLike` rebuilds the merged block with `createElement`, resurrecting an inert `<script src>` as a live, executing one on one tracked Backspace

**`src/tosijs-styled-editor.ts:1289`** · security, verified in a real browser engine

`canMergeBlocks` (:1318) denies only `ul|ol|dl|table` and `.editor-table`, so a top-level `<script>` passes. `trackStructuralEdit` then calls `blockLike(blocksOut[0])`, which does `document.createElement('SCRIPT')` and copies **every** attribute including `src`, and `blocksOut[last].after(merged)` inserts it.

A script parsed by the fragment parser has its "already started" flag set and can never run — that inertness is exactly what makes a stored payload of this shape survivable, and is what SECURITY.md leans on when it tells hosts to sanitize their corpus as part of upgrading. `createElement` clears the flag. Verified via `hj eval` in a live Chrome tab, inside a shadow root: an innerHTML-parsed inline script did not run (`originalRan: false`) while a `createElement` copy did (`copyRan: true`); with an external `src` (blob URL) the parsed one never fetched while the attribute-copied one **fetched and executed** in the embedding page's origin.

Branch-specific: on master this gesture was refused outright under tracking, and the untracked path appends into the _existing_ element and creates nothing.

**Non-security sibling of the same missing allowlist, worse than filed:** `<hr><p>hello</p>` + tracked Backspace produces `<hr>` with the merged text as children — and because a void element serializes without children, **the text is absent from `editor.value` entirely**. Content loss on round-trip, no attacker, no unsanitized corpus.

**Fix:** turn `canMergeBlocks` into an allowlist of block tags the editor authors (`p`, `h1`–`h6`, `div`, `blockquote`, `pre`, `li`, `figure`, …) — that kills the script case, the void case and the invalid-DOM case in one predicate and does not silently widen. Additionally make `blockLike` use `model.cloneNode(false)`: the spec's cloning steps propagate the already-started flag, so a clone of an inert script stays inert. Give `setBlockType` (`src/commands.ts:297`) the same allowlist.

### B‑4 — `data-author-name` serializes with `<` unescaped, so a display name containing `</style>`/`</xmp>` becomes live HTML on the next round trip

**`src/tosijs-styled-editor.ts:1050`** (same unescaped write at :931, :1360, :3763) · security, verified end to end

HTML attribute serialization escapes `&` and `"` but never `<`. `<style>`, `<xmp>`, `<title>`, `<textarea>`, `<noembed>`, `<noframes>`, `<plaintext>` re-parse their contents as raw text / RCDATA, so a `</style>` inside an attribute terminates the element and the rest parses as markup.

Reproduced in the project's own harness: doc `<style>p { color: red }</style><p>hello</p>`, `trackChanges = true`, `changeAuthor.name = 'A</style><img src=x onerror=alert(1)>'`, Backspace in the style block. `editor.value` comes back with the payload; assigning it to a second editor produced a real `<img src="x" onerror="alert(1)">`. **No external step triggers the re-parse** — `docHTML` _is_ the undo stack, so a single undo re-parses it in the same session, and `internals.setFormValue` carries it to every other reader.

Reachable without host cooperation: kilpi's forbidden-tag list drops `style`/`script`/`iframe`/`noscript` but **keeps `xmp`, `textarea`, `title`, `noembed`, `noframes`, `plaintext`** (verified against `node_modules/tosijs-kilpi/dist/index.js:14-29`). An ordinary collaborator pastes an `<xmp>`, makes one tracked deletion in it, and ships the payload with the host doing nothing but wiring `changeAuthor.name` to a profile name — which is precisely what `ChangeAuthor.name` ("What to show a reviewer") is for. Broader than the filed text: because kilpi is an _attribute_ blocklist, `data-*` survives paste verbatim, so a second paste of `<b data-x="q</xmp><img …>">hi</b>` inside an already-pasted `<xmp>` needs no tracked change at all. The defect class is _any attribute value serialized inside a raw-text element_.

Same mechanism corrupts with no attacker: a `<span class="sel-end caret">` left inside a `<style>` block round-trips into literal CSS text (observed in the same probe).

**Scope note, honestly stated:** the offending writes are byte-identical on master, so this is pre-existing in the 0.5.0 change-tracking subsystem rather than introduced here. It does not block this _merge_ relative to master so much as it blocks **any tag cut from it** — and this review exists to gate a tag. `grep` for mXSS/escapeAttr/"raw text" across `src/` and all `*.md` returns nothing; no mitigation exists.

**Fix:** keep the caret, the bounds markers and the change marks out of raw-text elements — they can never survive a round trip there, XSS aside. Add `script, style, xmp, iframe, noembed, noframes, plaintext, title, textarea` to the selectability/markable predicates (`isHitTestable` in `src/dom-utils.ts:190` and whatever `deletionTarget`/`leafNodes` consult), so a tracked edit inside one is refused the way a table-row deletion is. Reject any `<` in `changeAuthor.id`/`.name` at the seam. Note in SECURITY.md that `changeAuthor` is written into the document verbatim and is inside the host's trust boundary.

## MAJORS (fix now or file; none alone holds the tag, but B‑2 and B‑3 touch the same code)

### M‑1 — `preventDefault()` on `merge-blocks-not-mergeable` cannot perform the merge, so the documented override only drops tracking for a destroyed character

**`src/tosijs-styled-editor.ts:2812, 2887, 2965`** · correctness + blast-radius, verified twice

`overridden = true` routes the gesture through `asUntracked`, but the inner merge is re-gated by the _same_ `canMergeBlocks` that just failed (:2848, :2920), so it is skipped by construction. What still executes is `deleteEdgeCharacter`'s untracked branch. Measured: `<ul><li>one</li><li>two</li></ul><p>Beta.</p>`, tracking on, host calls `preventDefault()` exactly as README:456‑460 prescribes → `<li>tw</li>`, `changes.length === 0`, no `<tosi-del>`, no merge, `rejectChanges()` cannot restore it. Without the override, nothing happens at all — so overriding converts "nothing happens" into "content leaves the document unrecorded", the fails-open shape CLAUDE.md names as worse than no gate.

The selection path has the same shape at :2965‑2969: a whole cross-block selection's text is deleted with no marks and no `changes` entry.

README:459‑462 ("Calling `preventDefault()` performs the edit untracked — if tracking could have represented it, there would have been nothing to refuse") contradicts README:402‑405 and `canMergeBlocks`'s own doc comment, which both say this refusal is about valid DOM, not representability. Untested: the three override regression tests were removed in `9e5a3c1` and the surviving one exercises `deleteTableRow`, where the override genuinely works.

**Fix:** treat `merge-blocks-not-mergeable` as a non-overridable validity refusal — do not set `overridden` for it, drop the now-inert `run()` wrapper from both keystroke paths, and qualify README's sentence to say which reasons are overridable. Test that a `preventDefault`ed refusal leaves the list text byte-identical.

### M‑2 — `blockLike` copies `id`, so a pending merge puts duplicate ids in the live DOM and in `editor.value`

**`src/tosijs-styled-editor.ts:1288`** (and `resolvedClone` at :1267) · blast-radius, verified

`blockLike` copies `model.attributes` wholesale and strips only the four selection classes; `trackDeletion` leaves the struck original standing. Measured: `<h2 id="intro" class="lead" data-foo="1">Intro</h2><p>Body <a id="ref1">link</a>.</p>` + one Backspace → `doc.querySelectorAll('#intro').length === 2`, and `#ref1` is 2 as well because `resolvedClone` deep-clones inline content. A fix must cover **both** sites.

Severity is major, not blocker: the document lives in the shadow root, so host-document `getElementById`, `#intro` fragment navigation and cross-boundary `label[for]`/`aria-labelledby` are not affected. What survives scrutiny is that `value` and `internals.setFormValue` serialize both copies, so a document saved mid-merge carries invalid HTML and reproduces it on reopen, and an in-document `aria-labelledby` resolves to the struck copy. `blockLike` appears in no test file.

**Fix:** `block.removeAttribute('id')` (and `name`) in `blockLike`, and strip ids from the `resolvedClone` fragment; transfer the id in `acceptChanges`' `emptied` sweep so it lives on exactly one element at all times. Assert `querySelectorAll('#intro').length === 1` while the merge is pending.

### M‑3 — Four implementations of "merge two blocks" now coexist and have already drifted

**`src/tosijs-styled-editor.ts:1347, 2845, 2920, 3082`** (plus two list-item copies at :2402, :2480) · dryness + blast-radius, verified

The diff correctly unified the _predicate_ — `canMergeBlocks` is one method called from all four sites, and that fixed a live divergence (two sites checked only `.editor-table`, so a plain `<ul>` merged to loose text). The _mechanics_ stayed quadruplicated, and two divergences are already measurable:

- `<h1 id="title">Alpha heading</h1><p>Beta.</p>`, both blocks selected, `deleteSelection()`: untracked merges into `lastBlock` → `<p>Alpha headingBeta.</p>` (tag `p`, id lost); tracked builds from `blocksOut[0]` → proposes `<h1 id="title">`. **Same gesture, different block type and different id, depending only on whether tracking is on.** The raw family is not self-consistent either — the keystroke paths keep the _earlier_ block, the selection path keeps the _later_ one.
- Caret at start of the second block, Backspace: untracked gives `AlphBeta.` (the character eaten, per B‑2's mechanism), tracked+accept gives `AlphaBeta.`

Every future merge fix — trailing `<br>`, `dir`/`lang` reconciliation, whitespace at the join — must land in up to six places, and a fix landed only in the tracked copy reaches nobody with tracking off, which is the default.

**Fix:** extract one `mergeBlocks(first, last)` that both families call, the tracked path on cloned fragments and the raw paths on live blocks. If that is too large for this release, record an explicit keep-decision in `TODO.md` naming all six sites.
