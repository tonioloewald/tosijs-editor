## BLOCKERS

### B‑1 — Stacked merges and folded marks duplicate or resurrect text permanently, with no marks left to explain it

**`src/tosijs-styled-editor.ts:1290, 1317, 1243`** · correctness + security + coverage + ecosystem (four independent lenses, all verified)

`hasForeignChanges` asks only "is every mark mine, this session". It never asks whether a block is _itself_ a pending proposal, and `resolvedClone` flattens any mark that passes `isMine` regardless of its `data-change` id. Two reproduced consequences:

**(a) Two merges, then per-id resolution.** `<p>Alpha.</p><p>Beta.</p><p>Gamma.</p>`, tracking on. Backspace at the start of `Beta.`, then at the start of `Gamma.`. Merge #1's proposal becomes `blocksOut[0]` of merge #2 and is struck, giving `<p><tosi-del data-block-delete><tosi-ins data-block-insert>Alpha.Beta.</tosi-ins></tosi-del></p>`. `changes` reports 6 rows over 2 ids. Then:

- `rejectChanges(id1)` → `acceptChanges()` → **`Alpha. | Beta. | Alpha.Beta.Gamma.`**
- `acceptChanges(id2)` → `rejectChanges(id1)` → same

`changes` is then empty, every mark is gone, and `editor.value` / `internals.setFormValue` carry the duplicate. Undo can still step back, but nothing signals that anything went wrong.

**(b) A rejected insertion returns in the accepted document.** `<p>Alpha.</p><p>Beta.</p>`; type `xy` in the second block (insertion id A), then Backspace at its start (merge id B). `resolvedClone` bakes `xy` into B's proposal as plain text. `rejectChanges(A)` strips the mark from the struck original; `acceptChanges(B)` then yields `Alpha.Beta.xy` — **text the reviewer explicitly rejected is in the accepted document.** Round-trips through `value` and reproduces after reload.

Accept-all / reject-all happen to be clean, which is why the shipped toolbar hides this and why the suite is green. `merge === 'none'`, per-id resolution and `acceptChanges(id)` are all documented public API (README:312‑315).

**Fix:** absorb rather than stack — when `blocksOut` contains my own unresolved block-scoped proposal, re-use its `data-change` id and drop the superseded proposal block outright, so a chain of merges is ONE atomic group. That also kills M‑4 (the quadratic term) and half of M‑1. If absorbing is too large, fail closed: refuse a merge whose `blocksOut` hold any unresolved block-scoped mark, mine included, with its own reason. Either way `resolvedClone` must only flatten marks whose id is the gesture id. Test: two chained merges resolved in **every** order, asserting each word appears exactly once.

### B‑2 — `rescueCaretFrom` fires for every rejected insertion and hops out one level, so the caret is deleted or lands in the wrong block

**`src/tosijs-styled-editor.ts:1182, 1462`** · correctness + coverage (both verified) · introduced by this branch (`git log -S`: only `9e5a3c1`)

`rejectChanges` calls it for every `change.kind === 'insert'` with no `BLOCK_INSERT_ATTR` test, and `from = block.parentElement?.parentNode === doc ? block.parentElement : block` tests exactly one level. Reproduced:

- **Nested block-insert** (after two merges): `from` stays the ins, the ins is the del's only child, both siblings are null, and the `else marker.remove()` branch fires. `insertionPoint()` → **`null`**; the next keypress inserts nothing; `parts.doc.innerHTML` is byte-identical. There is no blur handler, so the document stays uneditable until a click re-seeds bounds — precisely the failure this method exists to prevent.
- **Plain inline insertion, one block** (`<p>Alpha.</p>`, type `xy`, reject): the markers are appended into `div.touch-affordances`. `insertionPoint()` is non-null, so the new assertions pass, but the next keystroke builds a `<tosi-ins>` inside chrome that `docHTML` detaches — **the character is silently lost**.
- **Plain inline insertion, two blocks**: the caret teleports to the _other_ paragraph and the next keystroke yields `Beta.Q` — **the user's text goes into the wrong paragraph, silently.** Also fires on `rejectChanges(id)` for a single row, hopping backward into the previous paragraph.

At v0.5.0 this flow dropped the keystroke; the branch converts a dropped keystroke into text inserted somewhere else. Rejecting an inline insertion is a shipped, documented 0.5.0 flow. Rejecting also leaves a residual `<p><tosi-del data-block-delete></tosi-del></p>` standing (same root cause as M‑1).

The three new assertions only check `expect(el.insertionPoint()).not.toBeNull()`, which is true in every broken case — **the test cannot go red.** No test anywhere asserts caret _location_ after a reject.

**Fix:** hop to the parent only when the mark carries `BLOCK_INSERT_ATTR`; otherwise place the markers adjacent to the mark inside its own parent. For the block case, walk up to the nearest direct child of `parts.doc` and skip hosts that are in `proposed`. Never `remove()` the markers — fall back to the doc element. Assert `insertionPoint()!.closest('p')!.textContent`, `!marker.closest('.touch-affordances')`, `!marker.closest('tosi-del')`, and that a following keypress lands text.

### B‑3 — The tracked keystroke merge now admits lists and grid tables: a paragraph is permanently lost and a list is destroyed. v0.5.0 refused this.

**`src/tosijs-styled-editor.ts:2741, 2814, 2994`** · correctness (selection path verified by the lens; **keystroke paths reproduced by me during triage**)

v0.5.0 gated every tracked cross-block merge on `refusesStructuralDelete && crossesBlocks` (confirmed at `v0.5.0:src/tosijs-styled-editor.ts:2530`). This branch replaced that blanket refusal with an unconditional tracked merge and added a list/table guard to **neither** keystroke path; `mergeable` (:2994, selection path) excludes only `.editor-table`.

Reproduced this session, tracking on, `press(el, 'Backspace')` with the caret at the start of the paragraph:

- **Grid table — permanent text loss.** `<ul class="editor-table" style="grid-template-columns: 1fr 1fr"><li>a</li><li>b</li></ul><p>Beta.</p>` → **no refusal event**; the proposal is `<ul class="editor-table"><tosi-ins data-block-insert><li>a</li><li>b</li><caret>Beta.</tosi-ins></ul>`; after `acceptChanges()` the document is `<ul class="editor-table"><li>a</li><li>b</li></ul>` and doc text is `"ab"` — **"Beta." is gone from the document entirely.**
- **Plain list — invalid DOM, paragraph destroyed.** `<ul><li>one</li><li>two</li></ul><p>Beta.</p>` → no refusal; after accept, `<ul><li>one</li><li>two</li>Beta.</ul>` — loose text as a direct child of `<ul>`.
- **Selection path (verified by the lens).** `<p>keep1 cut1</p><ul><li>cut2 keep2</li></ul>` cross-block selection delete → proposal `<p><tosi-ins data-block-insert>keep1 <li> keep2</li></tosi-ins></p>`, a bare `<li>` inside a `<p>`, which after accept **is** the document (and which real HTML re-parsing will split again on the next `value` round-trip — an `li` start tag closes an open `p`). The originals become `<ul><tosi-del data-block-delete><li>…</li></tosi-del></ul>`, i.e. the mark itself is now the list item — the exact shape `trackDeletion`'s own comment says to avoid.
- **List caret path.** Caret at the start of a `<p>` following a `<ul>`, Backspace → `<ul><tosi-ins data-block-insert><li>Item</li><caret>Beta.</tosi-ins></ul>`.

`merge-blocks-backward`/`-forward`/`-selection` were struck from the documented reason list, so a host can no longer even be told. README still says "lists and tables are still refused".

**Fix:** exclude `ul`/`ol` (including `.editor-table`) from the tracked merge on **all three** paths — not just `mergeable` — and refuse with an enumerated reason so the behaviour matches README. Tests: paragraph→list, list→paragraph, paragraph→grid-table, for Backspace, Delete and selection.

Keep every fence on a display-only language (`javascript`, not `js`) — README fences execute on the home page. Then rebuild so `docs/index.html`, `docs/docs.json` and `demo/docs.json` carry it (restart the dev server first — a delegated build reuses a stale config).
