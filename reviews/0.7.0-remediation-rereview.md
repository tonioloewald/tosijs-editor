## Major (verified, confirmed)

**M-A — The CHANGELOG's Fixed entry claims a paste divergence that is still present, and the new source comment covers for it.** `CHANGELOG.md:107`, inside the `### Fixed` bullet "**A touch Paste is tracked like any other paste**", states in past tense: "It also flattened rich clipboard content and ignored `pastemode`, so paste-by-touch and paste-by-keyboard produced different documents." Confirmed on this tree:

- the lozenge's Paste (`/Users/tonioloewald/tosijs-editor/src/tosijs-styled-editor.ts:4765-4781`) calls `navigator.clipboard.readText()` then `insertTransfer(null, text)`;
- with `html` null, `insertTransfer` takes the `this.pastemode === 'remove' || !html` branch unconditionally (`:4217`) and inserts a plain text node whatever `pastemode` says — and `:4217` is the **only** reader of `pastemode`, so touch always behaves as `'remove'`;
- the keyboard path reads `getData('text/html')` (`:4278`) and `handleCopy` writes `text/html` (`:4185`), so Cmd-C/Cmd-V on a bold word keeps the bold and tapping Paste loses it. The lozenge's Cut and Copy write plain text only as well, so touch flattens at both ends.

Only the tracking half of the entry's symptom list was fixed; the sentence covering the other two symptoms was not trimmed. `CHANGELOG.md` is in `package.json`'s `files`, so the claim ships in the npm tarball. Compounding it, `:4777` reads "Same three lines as `handlePaste`, deliberately" — handlePaste's lines pass `html`, these pass `null`, which is the one argument in question. Same family as this cycle's own B-2/B-3 (a published surface asserting the opposite of the tree), which CLAUDE.md records as having held the 0.6.0 tag three times.

Not a block (it is a docs line and a comment, and the underlying flattening is pre-existing and unchanged), but it is the one item worth fixing **before** the tag, because it is cheap and it is the defect class this release exists to close.

Cheapest correct fix, Tier 0 re-review only: drop the "It also flattened rich clipboard content and ignored `pastemode`…" sentence, say instead that the touch path stays plain-text-only (already filed as clipboard-fidelity #3175), and reword `:4777` to name what *does* match handlePaste (the tracking choreography) and what does not (the HTML half). Making the sentence true instead — `navigator.clipboard.read()` for `text/html` plus matching `write` on Cut/Copy — is new content arriving at the sanitizer's choke point and needs correctness + security + blast-radius over that diff.
