## BLOCKERS (1)

### B1 — Pasted and dropped HTML is inserted with `innerHTML` and no sanitization
`src/tosijs-styled-editor.ts:2405` · lens: security · **verified**

```ts
const temp = document.createElement('div')
temp.innerHTML = html          // clipboard / dataTransfer HTML, verbatim
while (temp.firstChild) { ip.before(temp.firstChild) }
```

`pastemode` defaults to `'merge'` (line 598), so this is the **default** branch — only `'remove'` takes the text path. `<script>` will not re-run, but `<img src=x onerror=…>`, `<svg onload=…>`, `<iframe src=javascript:…>` and `<style>` all do, in the embedding page's origin.

Reproduced under the project's own happy-dom setup by firing real `paste` and `drop` events: the payload lands in the doc **and** in `el.value` with handlers intact. Because `value` feeds `internals.setFormValue` and the undo stack (and `docHTML`'s setter is a raw `innerHTML` assignment at line 641), it is submitted to the host's backend and re-fires on every undo/redo — EXTENSIBILITY.md:88 advertises that rehydration as a feature. A CMS storing `value` has stored XSS for every later reader.

**This release is what re-opens it.** At base, `insertionPoint()` matched `input.caret` while the markers were already spans, so `insertTransfer()` bailed on its first line — paste and drop-insert were *dead* in 0.4.2–0.4.5. The `.sel-end` fix makes them live.

No hostile-input test exists anywhere; `grep -ri 'sanitiz\|XSS\|untrusted' src/ *.md` returns nothing.

**Fix:** sanitize inside `insertTransfer()` — the single shared choke point for paste and drop, by design — *before* the nodes leave the detached `temp` div. Drop every `on*` attribute; drop `script`/`iframe`/`object`/`embed`/`link`/`meta`/`base`; reject any `href`/`src`/`xlink:href` whose scheme is not http/https/mailto/`data:image`. ~25 lines. If the intent is that the *host* sanitizes, that must be a named, documented seam (an overridable `sanitize(html)` hook plus a prominent README warning), not silence.

**Re-review scope after remediation:** correctness + blast-radius over the remediation diff only, plus a security re-check that the filter is applied on **both** the paste and drop entries and **before** any node enters the document, never after insertion.

## MAJORS (5) — all adversarially verified

### F1 — Command strings interpolate URLs and filenames; `executeCommand` splits on `;`
`src/tosijs-styled-editor.ts:2526` (also `src/toolbar.ts:340,354`) · security · **verified**

`this.doCommand(\`insertImage ${url} ${file.name}\`)` meets `commandString.split(/;\s*/)` at `src/commands.ts:694-697`. Nothing escapes `;`.

1. **100% breakage.** `FileReader.readAsDataURL` is spec-mandated to emit `data:image/png;base64,…`, so *every* dropped image splits into `insertImage data:image/png` + a bogus `base64,…` command. Result: `<img src="data:image/png">` (broken) in the doc, in undo, and in the form value, plus `console.error('unrecognized command', …)`. Verified by running the actual regex.
2. **Injection.** A cross-origin drag source controls the File name (`dataTransfer.items.add(new File([...], 'a.png; setLink javascript:alert(document.domain)'))`), yielding an arbitrary second command. `setLink` (`commands.ts:319-341`) writes `href` with zero scheme validation.

*Correction to the reported framing:* this is **pre-existing**, not introduced here — `insertDroppedImages` is unchanged from `12b9afb`, and the old `insertionPoint()` also returned a live node. Severity holds on the breakage half alone.

**Fix:** give `doCommand`/`executeCommand` a structured form (`doCommand('insertImage', url, file.name)`) for every call site that interpolates a runtime value. String form stays for authored commands in `value` attributes. Escaping only the data URI leaves the filename injection open.

### F2 — Ctrl/Cmd-click follows a link's `href` through `window.open` with no scheme check
`src/tosijs-styled-editor.ts:2159` · security · **verified**

```ts
window.open(link.getAttribute('href') || '', link.getAttribute('target') || '_blank', 'noopener')
```

Reproduced twice in Chrome: `window.open("javascript:location.href='…?REPRO=yes'", '_self', 'noopener')` navigated the page. `noopener` does **not** prevent execution.

The verification found this is *worse* than reported: `_self`/`_top`/`_parent` are resolved at steps 4–6 of the spec's "choosing a navigable", **before** `noopener` is consulted at steps 7–8. So a pasted `<a href="javascript:…" target="_self">` executes in the host page's own document, same-origin — arbitrary script execution against the embedding application, not a severed blank window. The default `_blank` path is the weaker case.

Pre-existing (introduced in `1898bdf`, an ancestor of base) and strictly subsumed by B1 — fixing this alone secures nothing. **Fix:** allowlist the scheme via `new URL(href, location.href)` in a try/catch (http/https/mailto only); pass `_blank` unconditionally rather than a document-supplied window name.

### F3 — The ResizeObserver that replaced the 160 ms affordance timeout watches the **content** box, which does not change in the documented auto-height layout
`src/tosijs-styled-editor.ts:832` · correctness · **verified**

`updateTouchAffordances()` sets `paddingTop/Bottom = '52px'` then calls `positionAffordances()` **synchronously**, before the 0.15 s transition moves any text. The only corrective signal is `geometryObserver.observe(this.parts.doc, { box: 'content-box' })`.

- **Height-constrained host:** doc border-box fixed → padding shrinks the content box → observer fires → handles track. *This is the mode the commit's "measured: 5 callbacks" was taken in.*
- **Auto-height host (the documented default — README.md:6 and the module doc comment both show `<tosijs-styled-editor widgets="default" localized>` with no height):** the doc is content-sized, so padding grows the **border** box and pushes the host taller. Content-box height and width are unchanged → **the observer never fires**, nothing scrolls, window never resizes.

Decisive corroboration: `tosijs-editor-site.config.ts` `headExtra` injects `tosijs-styled-editor { height: 100% }` site-wide, so the project's own live examples run in the mode that works. The measurement is real but does not generalize.

Effect on a touch device with the documented markup: select a word on the first or last line (`startRect.top - 48 < docRect.top` is true for any first line, given only 8 px doc padding) → text slides ~44 px, the two drag handles and the context-menu button stay put, permanently, for the life of that selection. Dragging a handle then jumps. The painted caret strands on the way back out too — the exit path clears the padding and never calls `syncCaret()`. **Regression from v0.4.3**, whose `setTimeout(…, 160)` was correct in exactly this mode.

**Fix:** also `observe(this, { box: 'border-box' })` on the host with the same callback (the two observations together cover both modes — re-observing the *same* element replaces the first observation, so it must be a different element), or add `transitionrun`/`transitionend` on the padding property with a rAF pump. Then re-state the measurement comment at ~line 815 with the layout it was taken under; it currently reads as unconditional.

### F4 — Three of four runtime changes ship with no test that fails without them, and the layout-capable channel is run by nothing
`src/tosijs-styled-editor.test.ts:401` · coverage · **verified**

Proven by experiment: reverting the scroll/resize/ResizeObserver wiring, the affordance retiming, **and** the `openedBy` dismissal change still gives **177 pass / 0 fail** — byte-identical to HEAD. Base was 176; the entire +1 is the `insertionPoint` describe. `grep scroll src/*.test.ts` is empty.

The "happy-dom has no layout" defence does not cover these: `ResizeObserver` is already in the `windowProps` allowlist (`test-setup.ts:49`), listener wiring/teardown is plain DOM assertion, and the `openedBy` rule is pure event-identity logic.

The channel that *does* have layout — the ```test fence at `src/tosijs-styled-editor.ts:23` — **was red in shipped v0.4.3** (it asserted `doc.querySelector('input.caret')` against span markers) and nothing in `package.json` runs fences. The capability exists upstream but is unwired: `tosijs-ui`'s `devServer(config, opts?: { test?: boolean })` is never passed it here.

**Cost already realized:** at base, `insertionPoint()` returns null against real `createBounds()` output and `doCommand('insertTable')` creates nothing — with the suite 176/176 green. insertTable / insertImage / insertFootnote / setLink / annotate were silently dead for three published versions.

**Still open at HEAD:** 24 occurrences of `input.caret` / `<input class="sel-end caret">` remain in fixtures (`commands.test.ts` ×9, `tosijs-styled-editor.test.ts` ×15), and the mock context at `commands.test.ts:47-49` still defines `insertionPoint() { return root.querySelector('input.caret') }` — a shape the editor never produces.

### F5 — Nothing builds `dist/` before publish, and the registry shows it already bit: 0.4.4–0.4.6 were never published
`package.json:31` · blast-radius · **verified**

No `prepublishOnly` / `prepack` / `prepare`, no `.github/workflows`, `dist/` is gitignored while being the first entry in `files`, and `types`/`main`/every `exports` condition points into `dist/`. `npm publish` ships whatever happens to be in the publisher's working `dist/` — or, from a clean clone, **no dist at all**, which installs and then fails to resolve for every consumer.

`npm view tosijs-styled-editor time --json` returns exactly two entries (0.4.2, 0.4.3); `dist-tags.latest` is 0.4.3. **Every fix in this diff currently propagates to zero consumers.** (The working `dist/` is fresh right now — built today, stamped 0.4.6, zero `input.caret` — so the stale-artifact hazard is unarmed at this moment, but nothing in the repo keeps it that way.)

**Fix:** `"prepublishOnly": "bun run make && bun test && bun run lint"`, and verify with `npm pack --dry-run` that `dist/module.js`, `dist/index.js` and `dist/index.d.ts` are in the tarball before tagging.

### Unverified leads — sanity-check before acting

- **(unverified) The `openedBy` identity guard in `showTouchMenu` is unreachable** (`:2894`). `handleTouchContextMenu` calls `stopPropagation()` first (`:2764`) and is the sole call site, so the opening event never reaches the doc listener either way. - **(unverified) The `scroll` listener is bubble-phase on `doc`, and `scroll` does not bubble** (`:822`). Latent — nothing inside the doc scrolls today. Register `{ capture: true, passive: true }`.
- **(unverified) The build never prints the size of the artifacts consumers install** (`tosijs-editor-site.config.ts:91`). `libraryBuild` bundles `dist/index.js` and `dist/module.js` with `.quiet()`; only the doc-site bundle gets a size line. The hand-written "83.5kB → 70.8kB gzipped" comment at line 108 is already drifting (now 70.9). Pre-existing.
- **(unverified) `syncCaret` allocates a NodeList per frame to test emptiness** (`:952`). `querySelectorAll('.selected').length === 0` → `querySelector('.selected') === null`.
- **(unverified) The window `resize` listener and the ResizeObserver both fire for the same event** (`:828`). Note F3 changes the shape of this one — read them together before acting.
- **(unverified) `handleShortcut` interpolates `evt.key` into a CSS attribute selector without escaping** (`:2175`). Ctrl+Shift+`'` yields `[data-shortcut="ctrl+""]` → SyntaxError thrown out of the keydown listener. Use `CSS.escape`.
- **(unverified) CHANGELOG states 0.4.4–0.4.6 "were published"** (`CHANGELOG.md:13`). The registry has only 0.4.2 and 0.4.3 — see F5. The changelog's one job is telling consumers what reached them.

### Refuted — do NOT report as defects

- ~~"The geometry handler forces 2–3 document reflows per frame"~~ — **measured false.** The writes target out-of-flow overlays outside the `[part=doc]` subtree, so no document relayout occurs. Real cost: 0.0127 ms for `syncCaret` on a 2000-paragraph document vs 21.0 ms for a genuine relayout of the same tree; essentially flat with document size. The committed "0.015 ms" claim holds. Best available saving from batching: ~8 µs/frame.
- ~~"The `insertionPoint()` fix is untested where it matters"~~ — **false.** `src/tosijs-styled-editor.test.ts:401-433` was rewritten *in this diff* to use the real `el.selectable.createBounds()`, plus a second test driving `doCommand('insertTable')` through the live component. Both execute (8 pass under `-t "caret"`).
  - **Mined:** the residual is real but inert — `commands.test.ts:48`'s mock still hardcodes a marker shape that does not ship. That a competent reviewer read it as a live gap is the signal: file it as fixture-drift cleanup (below), not as a defect.
