## BLOCKER (must fix before tag)

### B-1 — the `tail.firstChild` gate over-corrects: a phantom `<tosi-ins>` duplicates a live change id in public `changes`

`src/tosijs-styled-editor.ts:975` · correctness + blast-radius · **verified by the review, and independently reproduced in this triage**

```
- if (tail.textContent) ins.after(tail)
+ if (tail.firstChild) ins.after(tail)
```

Per the DOM extract algorithm, a Range whose start sits inside a partially-contained child **clones that child into the fragment even when the extracted subrange is empty**. So with the caret at the end of a nested inline inside another author's insertion, `tail` comes back as `<tosi-ins data-change="c1"><b></b></tosi-ins>`: `textContent` empty, `firstChild` non-null. Pre-fix it was correctly dropped; post-fix it is re-attached.

**Reproduced in this session** (scratchpad test against the real component, repo untouched, `git status` clean). Doc `<p><tosi-ins data-change="c1" data-author="sam" data-session="other"><b>quick<caret></b></tosi-ins></p>`, `trackChanges = true`, type `X`:

```
DOM      <tosi-ins c1><b>quick</b></tosi-ins><tosi-ins new>X</tosi-ins><tosi-ins c1><b></b></tosi-ins>
changes  [{id:'c1',text:'quick'}, {id:'chg-…',text:'X'}, {id:'c1',text:''}]   ← 3 entries, two share c1
```

The plain-text control (`<tosi-ins c2>quick<caret></tosi-ins>`) is clean at 2 entries — isolating the cause to the element clone, which `normalize()` does not collapse.

**Why blocker:** `changes` and `value` are documented public API; a host review sidebar renders a ghost row with a duplicate key and an off-by-one "N changes pending" count. It **accumulates** (two edits in the same mark → five entries, `c1` three times) and **survives accept** — `acceptChanges()` leaves an empty `<b></b>` (or an empty `<a href>`) that nobody authored in the final clean document. Reachability is the primary documented gesture: `currentInsertion()` requires matching author _and_ session, so the split path fires for any edit inside another author's mark, or your own from a previous session. `acceptChanges(id)`/`rejectChanges(id)` filter on all matches, so id resolution is still correct — the damage is the lying instrument, the bloat, and the leak past accept.

**Fix — and the ORDERING MATTERS, which the finding does not say:**

The recommendation is `if (tail.firstChild && !blockIsEmpty(tail)) ins.after(tail)`. **Do not land that alone.** I measured `blockIsEmpty` through the real module:

```
<img> false   <br> false   <hr> false
<svg> TRUE    <video> TRUE   <canvas> TRUE   <audio> TRUE
```

Gating :975 on today's `blockIsEmpty` would **re-introduce the original B-1 data loss** for an svg/video/canvas tail — the exact bug this line was changed to fix, one media kind over. **Fix M-2 (invert the predicate) first, then gate B-1 on the corrected helper.** Land them as one change, not two.

**Tests required with the fix:** assert `el.changes.length === 2` and `new Set(ids).size === 2` for the `<b>quick|</b>` gesture (not merely that the `<img>` survives), and a case per media kind for the corrected predicate.

## Majors (non-blocking; file as scheduled follow-ups)

### M-1 — `deleteSelection` refuses the block merge silently: no event, no `preventDefault()` escape hatch, accepted document diverges from the untracked one

`src/tosijs-styled-editor.ts:2691` · correctness + blast-radius · **verified** (raised by two lenses, merged)

The first/last-block merge is gated on a bare `!this.refusesStructuralDelete` — the exact shape fix (2) just removed from the two table commands and `listForwardDelete`. Measured: `<p>x<sel>a</sel></p><p><sel>b</sel>y</p>` untracked → `<p>xy</p>`; tracked + `acceptChanges()` → `<p>x</p><p>y</p>`, with the refusal listener recording `[]`. A listener calling `preventDefault()` — README's documented override — changes nothing, because nothing is dispatched.

This is the **commonest gesture in the class** (select across paragraphs, Backspace): `keydown` routes both Backspace and Delete through `deleteSelection()` _first_, so the `merge-blocks-backward`/`-forward` refusals are shadowed for every selection delete. README:406-421 now states as contract that "a refusal fires a cancelable `structural-edit-refused` event", enumerates exactly six reasons, and says "**Calling `preventDefault()` performs the edit untracked**". Neither sentence is true here, and CHANGELOG:45 explicitly lists "selection deletes" among what IS tracked.

The guard predates the base (`a0e2c43`), so the code is outside the scoped diff — but the six-reason enumeration and the cancelable-event contract it violates are new this round, and the prior review's M-3 named `deleteSelection` explicitly in a five-item list of silent paths. **A fix aimed at a written five-item list reached four of them.** Not a blocker: nothing is lost or corrupted, and the conservative outcome stays recoverable.

### M-2 — `blockIsEmpty` is a closed allowlist that deletes svg/video/canvas-only blocks

`src/dom-utils.ts:430` · blast-radius · **verified** · **prerequisite for B-1's fix**

`!block.querySelector('img, hr, br, .editor-table, tosi-del, tosi-ins')` fails **toward deletion** for anything off the list. kilpi is a _blocklist_, so svg/video/canvas/audio/math/picture all survive paste into the document — confirmed by firing the editor's own paste handler. Driving the real path, a two-block selection delete whose last block holds `<svg>`/`<video>`/`<canvas>` removes the block **and the unselected media with it**; the identical case with `<img>` keeps the image. The caret guard does not protect it, because `deleteSelection` relocates `keptCaret` into the first block before the sweep runs. `acceptChanges` (:1236) calls the same helper and has the identical hole.

`blockIsEmpty` is exported from `dom-utils` and re-exported by `src/index.ts`, and npm shows only 0.4.2–0.4.5 — so **this helper enters the published API for the first time in this unreleased 0.5.0**, carrying the defect with it. Fix the predicate at the shared layer: empty = no non-whitespace text AND no element children other than the known box-free markers (`.sel-start`, `.sel-end`, `.caret`, `.spanified*`, `.touch-affordances`). That fails toward keeping content, which is the direction fix (1)'s own comment argues for.

### M-3 — the refusal/override policy is a structural twin in four shapes, and the divergence is already measurable

`src/tosijs-styled-editor.ts:2494` / `:2553` · blast-radius + correctness(DRY) · **verified**

`backspace()` and `forwardDelete()` are near byte-identical over ~55 lines — same `crossesBlocks`, same refusal `if`, same `overridden`, same `run()`, **and the same five-line comment copied verbatim into each**. This diff added the same ~12 lines to each copy independently. Three more shapes exist: `listForwardDelete` (`||` form, raw `nextLi.remove()`, no `asUntracked`), `removeListItem`, `deleteTableRow`/`deleteTableCol` (raw `.remove()`), and `deleteSelection` (silent — M-1).

The propagation cost is **demonstrated, not hypothetical**: M-3 of the previous re-review enumerated five silent paths by name; this remediation reached four. A measurable divergence already exists — the list merge ends `markBounds(); updateUndo('new')` (its own undo step) while the block merge ends with a coalescing `updateUndo()` (folded into the previous snapshot), so the same class of overridden structural edit has two undo granularities. Extract one `private structuralDelete(direction)` (or `mergeBlocks(from, into)` + a shared gate helper) so the gate, the override, the untracked window and the comment exist once.

### M-4 — two of the four fixes have an untested half; one is deletable outright with the suite fully green

`src/tosijs-styled-editor.ts:2186` · coverage · **verified**

Reverting `listForwardDelete`'s new gate to the old `!this.refusesStructuralDelete` leaves the suite at **272 pass / 0 fail**. Only 3 of the 6 README-documented reasons are asserted anywhere (`merge-blocks-backward`, `delete-table-row`, `delete-table-col`); `merge-blocks-forward`, `remove-list-item` and `merge-list-items` have none. Replacing **both** `run()` bodies with a bare `fn()` fails only the Backspace test — reverting only `forwardDelete`'s leaves 272/0, so that half is deletable with a green suite.

Nothing is broken today (all six reasons do fire; both override branches produce output byte-identical to the tracking-off baseline). But this subsystem's two prior remediations each shipped a new blocker behind a green suite, and an untested duplicated half is precisely the drift vector. A table-driven test over all six reasons closes the gate permanently.
