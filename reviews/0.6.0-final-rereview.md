## Blockers

### B-1 — Tracked cross-block merge leaves the empty block standing and reorders the document

`src/tosijs-styled-editor.ts:1149` (`trackDeletion`), `:1495`/`:1502` (`trackStructuralEdit`); surfaced via the new empty-block branch at `:3099`.

**Reproduced independently in this triage** (happy-dom, real `keydown` events, scratchpad probe only — no repo file touched). `<p>First</p><p></p><p>Third</p>`, caret in the empty block:

```
trackChanges: false → <p>First|</p><p>Third</p>                     (correct; what CHANGELOG promises)
trackChanges: true  → <p></p><p>First|</p><p>Third</p>              (after acceptChanges())
```

Identical for **Delete and Backspace**. The empty block survives accept, and `First` and the empty block have **swapped positions**. Same keystroke, same DOM, two different structures decided by a flag about review — precisely the class commit `33e1ee4` (M-1) was written to eliminate ("tracking on and off agree about the surviving element").

**Root cause is shared, not local to the new branch.** `trackStructuralEdit` calls `selectable.removeBounds()` (`:1495`) *before* `trackDeletion` (`:1501`). A block that `blockIsEmpty()` admitted contains only `.sel-start`/`.sel-end` (explicitly skipped by `blockIsEmpty`, `src/dom-utils.ts:482`), so by then it has no children at all; `if (asBlock && !asBlock.firstChild) continue` (`:1149`) therefore never strikes it, and `blocksOut[blocksOut.length - 1].after(merged)` (`:1502`) anchors the proposal *after* the block that survived.

Three further cases reproduce, all measured here:

- **Fully-struck victim** (`isFullyStruck` skip, `:1150`): `<p>First</p><p><tosi-del data-author="bo">Second</tosi-del></p>` + Backspace at the start of block 2 accepts to `<p></p><p>First|</p>` — a stray paragraph above the surviving text.
- **Inline-wrapper-only block**: `<p>First</p><p><b></b></p><p>Third</p>` + Delete accepts to `<p><b></b></p><p>First|<b></b></p><p>Third</p>`, because `isFullyStruck` delegates to `blockIsEmpty`, which calls a bare `<b>` empty.
- **Not confined to the new branch** — the ordinary cross-block path diverges too: caret at the START of `Third` + Backspace gives untracked `<p>First</p><p>|Third</p>` vs tracked-accepted `<p>First</p><p></p><p>|Third</p>`.

`rejectChanges()` restores correctly and no text is lost; **accept is the broken half**. Reachability is new in 0.6.0 — 0.5.x refused tracked cross-block merges outright (`merge-blocks-backward`).

**Why nothing caught it.** `describe('an empty block merges backwards, whichever key')` (`src/tosijs-styled-editor.test.ts:3284`) never sets `trackChanges`, so it exercises only the default. `bin/falsify.ts:115` guards that guarantee with `expect: ['merges backwards']`, which the untracked test alone turns red — so the new falsification lane reports the guarantee **GUARDED** while the tracked mode is entirely unexercised. Its green is right-looking and partial.

**`CHANGELOG.md:123-130` is false with tracking on** — the Fixed entry states unconditionally that "the block the caret was in stops existing".

**Fix at the shared layer, not in the new branch.** Either (a) have `trackStructuralEdit` remove a `blocksOut` member that `trackDeletion` declined to strike (nothing of the original is left to review in that case), or (b) anchor the proposal on `blocksOut[0]` (`blocksOut[0].before(merged)`) so the merged block lands where the surviving content was, and drop the empty/fully-struck victim explicitly. Then: add the tracked half of the empty-block describe (both keys, before and after `acceptChanges()`), add a fully-struck-by-another-author case and an inline-wrapper-only case, cover the plain cross-block path in both modes, and change the `falsify` mutation's `expect` so the guarantee is only `guarded` when a **tracked** test also goes red. Correct the CHANGELOG entry or make it true.

**Re-review scope:** correctness + blast-radius over the remediation diff. `trackDeletion`/`trackStructuralEdit` are shared by both keystroke paths, selection delete, paste restamp and merge chains — re-check the chain-of-merges and the list/table cases alongside the empty-block one.

*Two corrections to the original finding's narrative, neither affecting the defect: the empty-block branch arrived in `0ac635f`, which is **before** `33e1ee4` (M-1), not the commit after it; and because the plain cross-block path diverges too, the defect belongs to `trackStructuralEdit`/`trackDeletion`, not to the new branch.*

## Majors

### M-1 — `applyRevision()` gained a required 4th parameter with no CHANGELOG entry; a 3-argument call throws from inside the sanitizer

`src/changes.ts:314` (verified; `severityUncertain`)

`src/index.ts:5` is `export * from './changes'`, so `applyRevision` is package surface. Its signature went from `(node, revised, author)` to `(node, revised, author, session)` with `session` **required** — no default, no overload. Confirmed in the diff, alongside the same change to the private `mark()` (`:165`). It is a consequence of the good M-3 `stampMark()` extraction; the defect is the undocumented side effect.

A 3-arg call against HEAD:

```
TypeError: undefined is not an object (evaluating 'value.replace')
  at safeAttributeValue (src/changes.ts:117)  →  stampMark (:156)  →  mark (:168)  →  applyRevision (:330)
```

The message names neither the function nor the missing argument, and the stack bottoms out in the security primitive — a host wiring its own proofreader loop would reasonably start by suspecting its `changeAuthor`. Mitigating: the throw precedes `replaceChild`, so the document is left byte-identical; the failure is loud and non-corrupting.

The `[Unreleased]` CHANGELOG mentions neither `applyRevision` nor the new `stampMark` export (verified by grep — the only hit is the 0.5.2 prose at `CHANGELOG.md:140`). That omission fails this project's **own** standard: the same section documents the `stickySelection` default flip and three removed refusal reasons with before→after host code. Internal callers are fine (`src/tosijs-styled-editor.ts:916` passes `this.sessionId`), so the README-documented `reviseWith()` path is unaffected — the blast radius is hosts calling `applyRevision` directly.

**Fix:** make `session` optional with an explicit default (`session = ''`, skipping the attribute when empty) — which makes it non-breaking — **or** keep it required and add a Changed/BREAKING entry with the before/after call. Independently, make `safeAttributeValue` coerce (`String(value ?? '')`) so no write site can turn a missing attribution field into a TypeError from the security layer. List `stampMark` as a new export either way.

## Independent reproduction, and ONE correction (recorded 2026-10-06)

B-1 reproduced exactly, with my own probe:

```
Delete    untracked      : <p>First|</p><p>Third</p>
Delete    tracked+accept : <p></p><p>First|</p><p>Third</p>      ← empty block survives, order swapped
Backspace untracked      : <p>First|</p><p>Third</p>

<b></b>   tracked+accept : <p><b></b></p><p>First|<b></b></p><p>Third</p>
```

**Correction — the plain cross-block path does NOT diverge.** The report says the defect is "not
confined to the new branch" and cites a caret at the start of `Third` in
`<p>First</p><p></p><p>Third</p>`. But the block BEFORE that caret is the empty one, so that is
still the empty-block case. With two non-empty blocks the two modes agree:

```
plain untracked      : <p>First|Second</p>
plain tracked+accept : <p>First|Second</p>
```

So the blast radius is narrower than stated: it is specifically a `blocksOut` member that
`trackDeletion` DECLINES to strike — empty, inline-wrapper-only, or already fully struck. That
makes the root cause sharper rather than broader, and it is still a blocker.
