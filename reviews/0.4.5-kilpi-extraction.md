## Major (3)

### M1 — `isSafeNavigationUrl` has zero assertions left in this package, and both of its guard sites are ours, not kilpi's
`src/commands.ts:326` · lens: correctness · **(unverified)** · route: fix now, or `TODO.md`

The deleted block in `src/dom-utils.test.ts` was the only place this package asserted that `javascript:`, tab-smuggled `java\tscript:`, control-char-smuggled `javascript:` and `data:text/html` are rejected while `https:`/`mailto:`/relative survive. The replacement rationale at `dom-utils.test.ts:298` covers `sanitizeInPlace` only.

The two guard sites live **here**, not in kilpi, and both shipped as security fixes in 0.4.4:

- `src/commands.ts:326` — `setLink` refuses an unsafe scheme
- `src/tosijs-styled-editor.ts:2243` — the Ctrl/Cmd-click link opener

Neither has ever had a test. Confirmed by grep: `src/commands.test.ts` has six `setLink` tests, all with `https://example.com`; not one exercises the refusal branch. Two concrete costs: (a) `tosijs-kilpi` is `^0.1.0`, so a 0.1.1 that loosens the scheme normalizer weakens both guards with `bun test` still green and nothing in this repo's diff to show for it; (b) a refactor that drops `if (!isSafeNavigationUrl(url)) return` makes `setLink javascript:alert(1)` write a live href, and the suite passes.

**Fix:** three or four assertions pinning the *seam*, not kilpi's 223-fixture corpus — `setLink javascript:alert(1)` produces no `href` while `setLink https://example.com` wraps; the ctrl-click path refuses a `javascript:` href. That is asserting the contract this package depends on, so it does not re-create the two-copies problem the extraction removed.

### M2 — README, the only page npm renders, still says the dependency story is "Peer dependencies: `tosijs`, `tosijs-ui`" and describes the sanitizer as built-in
`README.md:66`, `README.md:122-166` · lens: blast-radius · **(unverified)** · route: fix now
*(merges the separate Installation and Security-section findings — same document, one edit)*

Three costs, all borne outside this repo:

1. **Supply chain.** This package now has its first real runtime `dependencies` entry — a 0.1.0 package that *is* the consumer's XSS defence — and Installation (line 66) lists only the two peers. An auditor building an SBOM from the README misses it.
2. **Threat model.** Lines 122-166, still stamped *"As of 0.4.4"*, enumerate the policy authoritatively — the exact forbidden-tag list, the scheme allowlist, the raster-`data:`-but-not-SVG rule — attributed to "the built-in sanitizer". It is not built in. kilpi's own SECURITY.md **leads** with the trade this README never frames as a decision: it is a denylist, *"unknown elements survive"*, and *"if protection from not-yet-known elements matters more to you than preserving unknown markup, use DOMPurify."* The README paraphrases the good half of that property (unregistered custom elements survive — "plugin markup is content, not a threat") and omits the bad half. If kilpi 0.1.x adjusts the list, a consumer install picks it up and this README keeps asserting the old policy with no diff here — the silent-drift mechanism the extraction removed, relocated into prose.
3. **Routing.** There is no `SECURITY.md` in this repo (confirmed). A researcher who finds a bypass files it against `tonioloewald/tosijs-editor`, which no longer contains the sanitizer; kilpi's tracker and disclosure path appear nowhere a consumer will see them.

**Fix:** Installation — note `tosijs-kilpi` is a runtime dependency installed automatically, and that the drop-in `dist/index.js` bundles it. Security — replace the enumerated list with the policy *shape* (denylist for elements, allowlist for URL schemes), one sentence on the unknown-elements trade, and a link to kilpi's SECURITY.md as authoritative; bump "As of 0.4.4" to 0.4.5. Keep in this README only what this package owns: the paste/drop choke point, the `editor.sanitize` hook, and the explicit NOT-sanitized list (which is good and should stay).

### M3 — `tosijs-kilpi: ^0.1.0` caps security-fix propagation at the 0.1.x line, and no version policy is written anywhere
`package.json:63` · lens: blast-radius · **(unverified)** · route: split — `TODO.md` (the range) + upstream issue on kilpi (the policy)

`^0.1.0` on a 0.x version resolves to `>=0.1.0 <0.2.0`. kilpi's own CHANGELOG records five bypass classes closed before 0.1.0, at least two of which changed observable behaviour (SVG animation elements added to the forbidden list; the control-character strip narrowed and then re-widened after `Chapter 3: Intro.html` was destroyed). Under ordinary 0.x convention the next behaviour-changing fix ships as 0.2.0 — at which point every installed `tosijs-styled-editor` stays on 0.1.x indefinitely: `npm update` will not move it, a lockfile install will not move it, and there is no advisory to make `npm audit` move it.

I confirmed the gap in the policy documentation: `grep -in "patch|minor|release|version"` over `node_modules/tosijs-kilpi/SECURITY.md` returns **nothing**. The file documents *how to report*, never *which line a fix lands on*. This package's CHANGELOG does not say either.

The CHANGELOG sells the extraction as ending the drift that produced 0.4.4's M1. A range that cannot cross a minor boundary reproduces that exact outcome for consumers — the fixed copy exists and never arrives.

**Fix (either is sufficient, settle it now while there is exactly one consumer):**
(a) state in kilpi's SECURITY.md — echoed in one line of this package's CHANGELOG — that while kilpi is 0.x, security fixes ship as PATCH releases on the current minor, so `^0.1.0` propagates them; or
(b) widen to `^0.1.0 || ^0.2.0` here and re-run the wiring tests against the newest resolution.
Either way, add a canary (`bun install --no-save tosijs-kilpi@latest && bun test`, or a Renovate rule) so a kilpi release this repo's tests would fail is caught here rather than in a consumer's browser.

## Minor (2)

### m1 — The published `dist/index.js` bundles three Apache-2.0 works with no NOTICE and no attribution surviving minification
`package.json:25` · lens: blast-radius · **VERIFIED (confirmed; severity adjusted major → minor)** · route: `TODO.md`

Reproduced end to end. `tosijs-editor-site.config.ts:114` builds the IIFE with `--minify` and **no** `--external` (the diff added `--external tosijs-kilpi` to the `module.js` line at :112 only), so `dist/index.js` (277 kB) embeds kilpi verbatim — `grep -c livescript dist/index.js` → 1, and that token appears nowhere in this repo's source. Minification strips every comment: grepping the built bundle for `kilpi`, `Apache`, `Loewald`, `Heiderich`, `DOMPurify` or `/*!` returns **zero hits**. `files` is `["dist", "!dist/*.tsbuildinfo", "README.md", "CHANGELOG.md", "LICENSE"]` — no NOTICE, and no NOTICE exists in the repo. All three bundled packages (`tosijs`, `tosijs-ui`, `tosijs-kilpi`) are Apache-2.0 and all three ship a NOTICE.

**Why minor, not major** (this is the verifier's adjustment, and I agree): the original write-up claimed a broken chain to Mario Heiderich's copyright. kilpi's NOTICE explicitly carves that out — the DOMPurify material is `test/dompurify-fixtures.mjs`, *"not part of the npm tarball"* — and §4(d) excludes notices that do not pertain to the derivative. What actually remains to propagate is `Copyright 2026 Tonio Loewald` three times over, matching this package's own `LICENSE`. No third party's attribution is lost, consumer-visible cost is zero, and legal exposure is nil. It is real license hygiene at the moment it is cheapest to close, not a release-relevant defect. (The write-up also conflated `docs/iife.js` — the 1.25 MB doc-site bundle — with the 277 kB `dist/index.js`; they are different artifacts.)
