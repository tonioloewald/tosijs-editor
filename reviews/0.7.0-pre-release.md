## Blockers

### B‑1 — `browser-tests/affordances.test.ts` is vacuous: all its vertical claims pass with the placement rule gutted
`browser-tests/affordances.test.ts:204` · correctness · **verified**

Measured in WebKit against the committed production bundle. Replacing `positionLozenge` with a stub that ignores the selection entirely and pins the lozenge to the bottom of the doc box leaves the lane at **5 PASS**. Two independent causes, each sufficient:

- **The probe never scrolls.** `[part="doc"]` on the example page is a 173.41px viewport with `scrollHeight` 2051 and `scrollTop` 0 (the editor is `height: 100%` inside a `tosi-example` whose default `--tosi-example-height` is 320px). Every paragraph the lane selects except index 0 is 354–1033px below the visible band, so `lozenge.style.top` is byte-identical **`273px`** for paragraphs 4, 6, 8, 10 and 12 — `bounds.bottom − size.height`, the terminal y clamp. Vertical placement is selection-independent for 7 of 8 calls. "Never intersects the line boxes" compares a lozenge at 738.98–784.98 against lines at 1134–1179: true for *any* lozenge inside the doc box.
- **The probe reads a stale rect.** `.touch-lozenge` carries `transition: left 0.1s, top 0.1s, opacity 0.1s` and the probe measures `getBoundingClientRect()` synchronously in the same task as the `selectionchanged` dispatch. Measured: inline `top` 273px while the rect still reported 676.86, settling to 738.98 after 250ms. Each assertion compares one selection's lines against the **previous** selection's lozenge box.

The existing precondition asserts only `lines.length > 0` and the dot diameter — neither notices an off-screen selection. The `flips below` test passes on stale geometry sitting exactly on the clamp (784.98 vs 784.98, a 0.00px margin). Tests 1 and 5 do carry information, though test 5 passes on a hair (|leftGap − rightGap| = 1.95 against a `< 2` threshold).

Why this is a blocker and not a missing test: `package.json`'s `releaseDoctor.attestedLanes: ["test:browser"]` means **the tag signs this lane**, and the CHANGELOG's Added entry states the geometric claims as "measured in real WebKit layout". Tagging publishes a measurement that was not taken. One correction to the finding, immaterial: it is not the "no room either side" branch (roomAbove is ~1000px, so `side` is chosen as `'above'`) — it is the final y clamp that erases the selection.

**Fix:** scroll the target paragraph into the doc's band before measuring and promote that to the describe's precondition; then either suppress the transition in the probe or read `lozenge.style.top/left`. Then **prove the lane can fail** — break `positionLozenge` and confirm red — before calling it fixed.

## Majors — fix now or file; they do not block

### M‑1 — The lozenge's Paste bypasses `insertTransfer`, so a touch paste is untracked while its own deletion is tracked
`src/tosijs-styled-editor.ts:4752-4765` · security + blast-radius + correctness (three lenses, deduped) · **verified, reproduced**

`insertTransfer` (`:4202`) is documented as *"the single shared choke point for paste AND drop… anything that reaches the document from outside passes through here"* and is the only place that calls `openInsertion()`, `this.sanitize(temp)`, `restampPastedChanges` or reads `pastemode`. The lozenge's Paste instead does `this.deleteSelection()` then a bare `ip.before(document.createTextNode(text))`.

Reproduced under happy-dom with `trackChanges = true`, pasting "XY" over a selected "on" in "one":

| path | result | `changes` rows | `rejectChanges()` |
| --- | --- | --- | --- |
| keyboard (`insertTransfer`) | `<tosi-ins data-change=…>XY</tosi-ins>` + the `<tosi-del>`s | 3 (1 insert, 2 delete) | `"one"` ✓ |
| lozenge | bare `XY` text node | 2 (delete only) | **`"XYone"`** |

The delete half is recorded, the insert half is not. Reject restores the original text and leaves the pasted text beside it — a document no gesture produces. Accept leaves content that was never under review. It also flattens rich clipboard content and ignores `pastemode`, so paste-on-touch and paste-on-keyboard produce different documents. Byte-identical to v0.6.1, so **latent, not newly introduced** — but this diff rewrote the function containing it and kept the twin, and the touch path is this release's showcase feature, so it is about to get more traffic. The sanitize bypass is not exploitable (plain text only) but means the choke point has a second door that only happens to be closed.

**Fix:** `this.deleteSelection(); this.insertTransfer(null, text); this.normalize(); this.updateUndo('new')`. Add a unit test asserting a `<tosi-del>` and `<tosi-ins>` sharing the gesture, and a falsify mutation that no-ops the `insertTransfer` call.

### M‑2 — `Copy` has no empty-selection guard, so one tap on a bare caret wipes the system clipboard
`src/tosijs-styled-editor.ts:4746-4749` · correctness + blast-radius (deduped) · **verified**

`Cut` guards (`const text = selectedText(); if (!text) return`); the adjacent `Copy` calls `navigator.clipboard.writeText(selectedText())` unconditionally. One precondition, two copies, one drifted. A bare caret reaches the lozenge: `updateTouchAffordances` gates only on `isTouchInteraction` plus the existence of `.sel-start`/`.sel-end`, and `createBounds()` creates both on every tap. With a collapsed caret `markRange` computes `firstIdx > lastIdx`, never marks anything, and `selectedText()` is `''` — confirmed by probe: `.selected` count 0, `Cut` → zero writes, `Copy` → `[""]`, lozenge inline display `flex`. No disabled state exists for any lozenge item.

The missing guard is pre-existing (identical in `v0.6.1`), but **this diff is an exposure regression**: the ⋮ button plus a separately-built menu became a condensed lozenge whose inline items are exactly Cut/Copy/Paste, so two taps became one, from a bar that now appears unasked on every caret placement and is positioned over the text. Destroys state outside the editor with no undo and no receipt.

**Fix:** hoist the precondition out of both and disable or hide Cut/Copy/Delete while the selection is collapsed. Worth deciding separately whether a collapsed caret should get the lozenge and both handles at all — iOS draws no handles for a caret and offers Select / Select All / Paste. README and CHANGELOG both describe the affordances as what *"a selection made or adjusted by touch"* gets, which is not what the code does.
