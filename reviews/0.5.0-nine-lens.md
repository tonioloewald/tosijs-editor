## BLOCKERS — must be fixed before tagging

### B1 · `editor.value` throws `NotFoundError` and permanently destroys every spelling mark

`src/tosijs-styled-editor.ts:686-713` · lenses: correctness + coverage · **verified**

The `docHTML` getter captures each `<tosi-misspelling>`'s `nextSibling`, unwraps **all** marks, then re-inserts each one before its saved anchor. When mark A's anchor is mark B, B is already detached and `insertBefore` throws — and the throw lands mid-restore, so every mark stays unwrapped and is gone for good.

Adjacency is routine, not exotic. Marks are separated only by the empty text nodes `Range.insertNode` leaves behind, and **any** `normalize()` collapses them — `dropMarksFor` calls `parts.doc.normalize()`, and `Selectable.normalize()` runs on nearly every edit path. Reproduced two ways:

- `<p>東京都庁前駅</p>` → 4 marks → `acceptWord('東京')` → `value` throws, marks 4 → 0.
- Latin: `<p>teh borwn</p>`, both flagged, one Backspace deleting the separating space → marks 2 → 0, silently.

Because `updateUndo()` reads `docHTML` as its first act inside the keypress listener, one keystroke in such a document wipes the marks, skips the undo snapshot and `setFormValue`, leaves `.touch-affordances` detached, and `dispatchEvent` swallows the exception.

**Fix:** restore in reverse (`[...restore].reverse()`), or anchor on a placeholder comment node. Verified in isolation that reverse order round-trips correctly. Add tests for two adjacent marks in one text node after `normalize()`, and for a CJK paragraph with one word accepted.

### B2 · Spell check flags correct words and `reviseWith` sends half-words to the LLM

`src/spelling.ts:102` and `src/tosijs-styled-editor.ts:786` · lens: correctness · **verified**

Both new paths do `createTreeWalker(root, SHOW_TEXT)` over live text nodes. The caret/selection bounds markers are real `<span>`s that split those nodes, and neither path runs the choreography CLAUDE.md documents (`resetBounds` → `spanify(root,false)` → `markBounds` → `removeBounds`) — the choreography that exists precisely to prevent this. There is no blur handler anywhere, so once a click places the caret the markers stay indefinitely.

- `<p>the brown fox</p>`, caret after "br" → checker asked `["the","br","own","fox"]` → `errors: ["br"]`, a correctly-spelled word marked, and in a real browser `setValidity({customError:true}, '"br" may be misspelled')` blocks form submit.
- `reviseWith` on the same shape sends the proofreader `["The quick br", "own fox jumps."]` — two fragments, one ending mid-word, rewritten independently into garbage tracked changes.

Every existing test sets `parts.doc.innerHTML` and never places a caret, so the document is always one unsplit text node.

**Fix:** run the documented choreography at the top of both entry points, or build one block-level text index with a node/offset map and share it with `Selectable.textIndexOf`. Add tests that place a caret inside a word before checking and before revising.

### B3 · With `trackChanges = true`, deletion fails OPEN — content leaves with no `<tosi-del>` and no recorded change

`src/tosijs-styled-editor.ts:2172, 2207, 2254, 2290` (+ `1812`, `1843`, `2766`, `2790`) · lenses: correctness + security + dryness + coverage · **verified**

`trackDeletion` has exactly **one** call site (`:2273`, the leaf-node loop in `deleteSelection`). Six other deletion paths delete raw:

- **Collapsed-caret Backspace/Delete** — the commonest gesture in the editor. `<p>hello</p>`, caret at end, one Backspace → `<p>hell</p>`, `tosi-del` count 0, `changes.length` 0. Unrecoverable; `rejectChanges()` cannot restore it.
- **Fully-selected interior blocks** — `block.remove()` at `:2254` runs _before_ any `trackChanges` check. Three-paragraph selection → the middle paragraph is gone with no mark. On exact block boundaries `deleteSelection()` then returns `false` and the keydown handler falls through to `backspace()`, eating an extra character.
- Also untracked: `listBackspace`, `listForwardDelete`, both table-cell branches, and the empty-block sweep (which can remove a block containing a freshly-created `<tosi-del>`).

README and CHANGELOG both state "deleting wraps in `<tosi-del>` instead of removing", with exactly two carve-outs (your own open insertion; text already inside a `<tosi-del>`). Neither covers a caret or a whole block. `grep Backspace` over the test file returns nothing — no test dispatches a deletion keystroke with tracking on.

Related, same root: `trackDeletion` wraps `topSingleParentAncestor(node)`, so a whole-block deletion yields `<tosi-del><p>…</p></tosi-del>` at doc top level, and `block()` then returns the `tosi-del` — mis-targeting `setBlockType`, `selectedBlocks` and Enter handling. A three-block delete also produces nested `tosi-del` marks and collapsed block structure.

**Fix:** route every destructive path through one tracking-aware `removeOrTrack(node)`. If that is too large for 0.5.0, scope the README/CHANGELOG claim honestly to selection deletes and make caret deletion a no-op or warning while tracking is on. **Re-review scope:** correctness + blast radius over the remediation diff (deletion paths touch list-item merge, table-cell delete, block merging, and accept/reject + `normalize()` semantics).

### B4 · The release is not versioned — package.json 0.4.5, CHANGELOG `[Unreleased]`, and the build ordering matters

`package.json:3`, `src/version.ts`, `CHANGELOG.md:8` · lenses: correctness + docs + dx · **verified**

Confirmed this session: `package.json` is `0.4.5`, `src/version.ts` exports `'0.4.5'`, CHANGELOG's top section is `## [Unreleased]` with zero occurrences of `0.5.0` anywhere, `npm view` shows 0.4.5 already published as `latest`, and `git rev-list --count v0.4.5..HEAD` = **9**. That is verbatim `release-doctor.ts`'s release-identity FAIL branch. Publishing is rejected by the registry; tagging first ships a build whose exported `version` (public API via `src/index.ts:9`) names its predecessor.

Ordering is load-bearing, not paperwork: `prebuild` stamps `src/version.ts` from package.json, and the doc system stamps `llms.txt` / `docs/llms.txt` — both currently read `v0.4.5` and both are committed. Bumping and committing **without** re-running `bun run make` publishes a site and LLM manifest advertising 0.4.5.

**Fix (as the release cut):** bump package.json → 0.5.0; retitle `## [Unreleased]` → `## [0.5.0] - 2026-09-21` with a fresh empty `[Unreleased]`; sweep the five `0.4.6` references (below); run `bun run make`; commit the regenerated `src/version.ts`, `llms.txt`, `docs/llms.txt` and `docs/`; then tag. **Re-review scope: Tier 0 only.**
